# v0.1.1 findings: Far fixes after the first real run

Three Far deviations were reported while trying the v0.1.0 portable build.

## Left arrow jumped to the left panel
- **Cause.** WPF processes a key message (in `HwndSource`'s `ThreadFilterMessage`) before `GlobalKeyHook` sees it in `ThreadPreprocessMessage`.
  - An arrow key that no WPF element handled ran WPF directional navigation. `DirectionalNavigation="None"` on the window and the workspace did not stop it.
  - So Left in the right panel moved keyboard focus to the left panel and was marked handled, and the hook never saw it. The trace showed no `key None+Left` line at all.
  - In the left panel nothing lay further left, so the key fell through and worked. That is why the bug only showed on one side.
- **Fix.** `MainWindow.OnPreviewArrowKey`: while a panel has focus, arrows are taken in the window's `PreviewKeyDown`. They are routed through `OnGlobalKey`, the same path as every other key, and marked handled.
  - Keys typed into the terminal never reach WPF events, so the hook still handles those.
- **Far behaviour.**
  - In multi-column modes Left / Right move to the same row of the neighbouring column, clamped to the first or last file.
  - In one-column modes they act as Home / End. They used to move by a page.

## Ctrl+P: hide / show the inactive panel
- Hides `Other(_active)`. `WorkspaceLayout` already places the terminal at full height in the freed half.
- Pressing it again shows both panels.
- Added to F9 → Commands and to F1 help.

## Ctrl+U with one panel
- **Before.** `SwapPanels` swapped only the panel objects, so the visible active panel ended up in the hidden slot.
- **Now.** Visibility follows the panel, as in Far.
  - With one panel visible, the panel and the terminal trade sides.
  - A panel hidden with Ctrl+F1 / Ctrl+F2 stays hidden.
  - The Ctrl+O / Ctrl+P restore state is swapped too.

## Tab with one panel
- With the inactive panel hidden (Ctrl+P), the terminal stands in for the other panel, so Tab moves focus between the panel and the terminal.
- **In the terminal.** Tab is needed for completion, so it goes back to the panel only on an empty command line.
  - Only PSReadLine knows the buffer, so the integration script binds Tab.
  - On an empty line, while the host's `tab-to-panel` flag file exists in the channel, Tab sends `OSC 7731;habi;focus-panel`.
  - Otherwise it calls the function Tab was bound to before: `TabCompleteNext` by default, or `MenuComplete` from the user's profile.
- **The flag.** `ShellHost.TabToPanel` is the flag. The window sets it whenever exactly one panel is visible.
- **Test.** A shell test covers the request on an empty line, completion on a non-empty line and the flag being off.
- An earlier attempt made Tab show the hidden panel in place; that misread the request and was replaced.

## Panel layout keys from the command line
- **Before.** With focus in the terminal, Ctrl+U / Ctrl+P went to pwsh and PSReadLine echoed `^U` / `^P`.
- **Now.** Ctrl+U, Ctrl+P and Ctrl+F1 / Ctrl+F2 work from the terminal, as they do from Far's command line.
  - Only at the prompt (`ShellState.Idle`); a running program still gets every key.
  - Focus stays in the terminal.

## White bar beside the terminal
- **Cause.** The bar was the terminal control's WPF `ScrollBar`, drawn in the light system style. The help and settings pages had the same light scroll bars.
- **Fix.** An implicit VS Code-like `ScrollBar` style:
  - 10 px wide, no arrows.
  - Transparent track, so the owner's background shows through.
  - The slider uses the theme's `scrollbarSlider.*` colours (normal, hover, drag), with their alpha kept.

## Panel columns jumped with the cursor
- **Cause.** `WorkspaceLayout.MeasureOverride` measured every child with the whole workspace size.
  - With a long file name under the cursor, the status line wanted more width than the panel's slot.
  - WPF then arranged the panel at its desired width and clipped it, so the Medium columns moved right and the right column was cut off. They moved back on a short name.
- **Fix.** Each child is measured in its own slot. Layout properties now invalidate measure, not only arrange.

## Own title bar with the menu
- **Chrome.**
  - `WindowChrome`: caption height 30, the system resize border, and a 1 px glass frame, so DWM keeps the shadow and Windows 11 rounded corners.
  - `Widgets/TitleBar` holds the icon, the menu headers (hit-test visible in the chrome) and the caption buttons.
  - The caption buttons use the Segoe Fluent Icons / Segoe MDL2 Assets glyphs.
- **Menu.** The F9 popup draws its own headers exactly over the title bar's ones. Both are built by `TopMenu.CreateHeader`.
  - A drop-down wider than the header strip used to centre that copy 12 px off. The copy is now left-aligned.
- **Snap Layouts.** `WM_NCHITTEST` over the maximize button returns `HTMAXBUTTON`. Its clicks therefore arrive as `WM_NCLBUTTONDOWN` / `WM_NCLBUTTONUP` and are handled there.
- **Maximized.** The window reaches past the screen by the sizing frame plus the padded border, both taken from `GetSystemMetrics`, so the content is inset by that much.
  - `SystemParameters.WindowResizeBorderThickness` alone left 4 px cut off.
  - The inset is also applied on load, because a restored maximized placement raises no `StateChanged`.
- **Colours.** `titleBar.activeBackground` / `titleBar.activeForeground` from the theme. The bar dims while the window is inactive.
- **Checked in the UI:** header click, F9 and arrows, Snap Layouts flyout on hover, maximize via the button and a caption double-click, F9 while maximized.
- **Screenshots.** `PrintWindow` does not capture popups, so menu screenshots need a real screen capture.

## Default view mode
- New panels start in **Medium** (two name columns), Far's default.
- A state.json that already stores a view mode keeps it. A v0.1.0 copy that was already run reopens in Full until Ctrl+2 is pressed.

## Verified

  - Fresh state opens in Medium.
  - Left / Right stay inside the right panel.
  - Ctrl+P moves the terminal into the right half; Ctrl+U moves it to the left; Ctrl+P restores two panels with the terminal at the bottom.
